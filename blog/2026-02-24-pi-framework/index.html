Как создать кастомный агентный фреймворк с PI: стек агентов в основе OpenClaw

24 февраля 2026 · 15 мин чтения
Оригинал: Nader Dabit на X.com

PI is a toolkit for building AI agents. It's a monorepo of packages that layer on top of each other:

  • pi-ai — обработка LLM-коммуникации между провайдерами
  • pi-agent-core — добавляет агентный цикл с вызовом инструментов
  • pi-coding-agent — полноценный агент кода со встроенными инструментами, персистентностью сессий и расширяемостью
  • pi-tui — терминальный UI для создания CLI-интерфейсов

Это те же самые пакеты, которые лежат в основе OpenClaw. Это руководство проходит через каждый слой, постепенно доходя до полноценного агента с терминальным UI, персистентностью сессий и кастомными инструментами.

Понимая, как компоновать эти слои, вы сможете строить продакшн-уровневый агентный софт на своих условиях — без привязки к конкретной абстракции.

PI создан @badlogicgames. Вот его отличный разбор архитектурных решений. Туториал содержит много кода и поэтому также доступен как Markdown. Больше материалов от автора — здесь.

Каждый слой добавляет новые возможности.

pi-ai — вызывает любую LLM через единый интерфейс: Anthropic, OpenAI, Google, Bedrock, Mistral, Groq, xAI, OpenRouter, Ollama и другие. Стриминг, завершения, определения инструментов, отслеживание затрат.

pi-agent-core — оборачивает pi-ai в агентный цикл. Вы определяете инструменты, агент вызывает LLM, выполняет инструменты, возвращает результаты и повторяет до завершения.

pi-coding-agent — полноценный агентный рантайм. Встроенные файловые инструменты (read, write, edit, bash), персистентность сессий через JSONL, уплотнение контекста, скиллы и система расширений.

pi-tui — библиотека терминального UI с дифференциальным рендерингом. Отображение Markdown, многострочный редактор с автодополнением, спиннеры и обновления экрана без мерцания.

Требования:

  • Node.js 20+
  • API-ключ хотя бы одного провайдера (Anthropic, OpenAI, Google и т.д.)

Установка:

mkdir pi-agent && cd pi-agent
npm init -y
npm install @mariozechner/pi-ai @mariozechner/pi-agent-core @mariozechner/pi-coding-agent @mariozechner/pi-tui chalk
npm install -D typescript @types/node tsx

Установите API-ключ:

export ANTHROPIC_API_KEY=sk-ant-...
# or
export OPENAI_API_KEY=sk-...

Слой 1: pi-ai

Ваш первый LLM-вызов — создайте basics.ts:

Создайте basics.ts:

import { getModel, completeSimple } from "@mariozechner/pi-ai";

async function main() {
  const model = getModel("anthropic", "claude-opus-4-5");

  const response = await completeSimple(model, {
    systemPrompt: "You are a helpful assistant.",
    messages: [
      { role: "user", content: "What is the capital of France?", timestamp: Date.now() }
    ],
  });

  // response is an AssistantMessage
  for (const block of response.content) {
    if (block.type === "text") {
      console.log(block.text);
    }
  }

  console.log(`\nTokens: ${response.usage.totalTokens}`);
  console.log(`Stop reason: ${response.stopReason}`);
}

main();

Запустите:

npx tsx basics.ts

getModel ищет модель по провайдеру и ID из встроенного каталога PI (2000+ моделей). completeSimple отправляет сообщения и возвращает полный AssistantMessage, когда модель завершила работу.

Ответ содержит массив .content из типизированных блоков — text, thinking или toolCall — плюс .usage для подсчёта токенов и .stopReason для объяснения остановки ("stop", "toolUse", "length", "error", "aborted").

Стриминг

completeSimple ждёт полного ответа. Для вывода в реальном времени используйте streamSimple:

import { getModel, streamSimple } from "@mariozechner/pi-ai";

async function main() {
  const model = getModel("anthropic", "claude-opus-4-5");

  const stream = streamSimple(model, {
    systemPrompt: "You are a helpful assistant.",
    messages: [
      { role: "user", content: "Explain how TCP works in 3 sentences.", timestamp: Date.now() }
    ],
  });

  for await (const event of stream) {
    switch (event.type) {
      case "text_delta":
        process.stdout.write(event.delta);
        break;
      case "done":
        console.log(`\n\nTokens: ${event.message.usage.totalTokens}`);
        break;
      case "error":
        console.error("Error:", event.error.errorMessage);
        break;
    }
  }
}

main();

У каждого провайдера свой формат стриминга — Anthropic, OpenAI и Google делают это по-разному.

streamSimple нормализует их в единый набор событий: start, text_start, text_delta, text_end, thinking_start/delta/end, toolcall_start/delta/end, done и error.

Напишите обработчик стриминга один раз — он работает с любым провайдером. В большинстве случаев вас интересуют text_delta (куски текста) и done (финальное сообщение).

Можно также await'ить финальное сообщение напрямую:

const stream = streamSimple(model, context);
const finalMessage = await stream.result(); // AssistantMessage

Переключение провайдеров

Переключитесь на другой провайдер, изменив только вызов getModel. Остальной код остаётся прежним.

// Just change this line - everything else stays the same
const model = getModel("anthropic", "claude-opus-4-5");
// const model = getModel("openai", "gpt-4o");
// const model = getModel("google", "gemini-2.5-pro");
// const model = getModel("groq", "llama-3.3-70b-versatile");

const stream = streamSimple(model, context);

Каждый провайдер требует своего API-ключа в переменных окружения (ANTHROPIC_API_KEY, OPENAI_API_KEY, GEMINI_API_KEY, GROQ_API_KEY и т.д.).

Также можно определить кастомные модели для self-hosted эндпоинтов:

import type { Model } from "@mariozechner/pi-ai";

const localModel: Model<"openai-completions"> = {
  id: "llama-3.1-8b",
  name: "llama-3.1-8b",
  api: "openai-completions",
  provider: "ollama",
  baseUrl: "http://localhost:11434/v1",
  reasoning: false,
  input: ["text"],
  cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 },
  contextWindow: 128000,
  maxTokens: 8192,
};

Под капотом pi-ai использует официальные SDK провайдеров. Поле api определяет, какой SDK обрабатывает запрос — "openai-completions" маршрутизируется через OpenAI SDK, поэтому работает с любым OpenAI-совместимым эндпоинтом (Ollama, vLLM, Mistral и т.д.).

API-ключи берутся автоматически из переменных окружения по имени провайдера. Для провайдера, которому нужен ключ, установите соответствующую переменную окружения или передайте его явно:

const stream = streamSimple(localModel, context, {
  apiKey: "your-api-key",
});

Уровни мышления:

Модели с поддержкой расширенного мышления (Claude, o3, Gemini 2.5) включаются через опцию reasoning. По умолчанию выключено.

const stream = streamSimple(model, context, {
  reasoning: "high", // "minimal" | "low" | "medium" | "high" | "xhigh"
});

При включении стрим дополнительно эмитирует события thinking_delta вместе с text_delta.

Слой 2: pi-agent-core

pi-ai позволяет разговаривать с LLM. pi-agent-core позволяет LLM отвечать — с инструментами.

Класс Agent выполняет стандартный агентный цикл: отправляет сообщения в LLM, выполняет вызовы инструментов, возвращает результаты, повторяет до остановки модели.

Определение инструментов

Инструменты используют схемы TypeBox для типобезопасных определений параметров:

import { Type } from "@mariozechner/pi-ai";
import type { AgentTool } from "@mariozechner/pi-agent-core";

const weatherParams = Type.Object({
  city: Type.String({ description: "City name" }),
});

const weatherTool: AgentTool<typeof weatherParams> = {
  name: "get_weather",
  label: "Weather",
  description: "Get the current weather for a city",
  parameters: weatherParams,
  execute: async (toolCallId, params, signal, onUpdate) => {
    // params is typed: { city: string }
    const temp = Math.round(Math.random() * 30);
    return {
      content: [{ type: "text", text: `${params.city}: ${temp}C, partly cloudy` }],
      details: { temp, city: params.city },
    };
  },
};

Определите схему как отдельную переменную и передайте как generic-параметр AgentTool<typeof schema> — это даёт TypeScript информацию для правильного вывода типа params внутри execute.

Каждый инструмент имеет:

  • name — идентификатор, по которому LLM вызывает инструмент
  • label — человекочитаемое имя
  • description — объясняет LLM, когда и как использовать инструмент
  • parameters — схема TypeBox; валидируется через AJV перед выполнением
  • execute — запускается при вызове инструмента; возвращает content (для LLM) и details (для UI)

Колбэк onUpdate позволяет стримить частичные результаты во время выполнения — полезно для долгих инструментов вроде bash-команд.

Создание агента

Подключите weather-инструмент к модели и функции стриминга. Обработку событий, промптинг и полный рабочий пример добавим в следующих секциях.

import { Agent } from "@mariozechner/pi-agent-core";
import { getModel, streamSimple } from "@mariozechner/pi-ai";

const model = getModel("anthropic", "claude-opus-4-5");

const agent = new Agent({
  initialState: {
    systemPrompt: "You are a helpful assistant with access to tools.",
    model,
    tools: [weatherTool],
    thinkingLevel: "off",
  },
  streamFn: streamSimple,
});

Agent принимает initialState (системный промпт, модель, инструменты, уровень мышления) и streamFn — функцию, которая реально вызывает LLM. Передача streamSimple из pi-ai подключает агента к провайдеру, указанному в модели.

Стрим событий

Подпишитесь на события, чтобы видеть, что делает агент:

agent.subscribe((event) => {
  switch (event.type) {
    case "agent_start":
      console.log("Agent started");
      break;

    case "message_update":
      // Streaming text from the LLM
      if (event.assistantMessageEvent.type === "text_delta") {
        process.stdout.write(event.assistantMessageEvent.delta);
      }
      break;

    case "tool_execution_start":
      console.log(`\nTool: ${event.toolName}(${JSON.stringify(event.args)})`);
      break;

    case "tool_execution_end":
      console.log(`Result: ${event.isError ? "ERROR" : "OK"}`);
      break;

    case "agent_end":
      console.log("\nAgent finished");
      break;
  }
});

Полный список событий:

agent_start
agent_end
turn_start
turn_end
message_start
message_update
message_end
tool_execution_start
tool_execution_update
tool_execution_end

Запуск агента

await agent.prompt("What's the weather in Tokyo and London?");

Готово. Агент:

  1. Отправляет ваше сообщение в LLM
  2. LLM решает вызвать get_weather для Токио
  3. Агент выполняет инструмент, возвращает результат
  4. LLM вызывает get_weather для Лондона
  5. Агент снова выполняет, возвращает результат
  6. LLM выдаёт финальный текстовый ответ

Цикл писать не нужно — агент сам его обрабатывает.

Полный пример

Вот полный рабочий пример с двумя инструментами:

import { Agent } from "@mariozechner/pi-agent-core";
import { getModel, streamSimple } from "@mariozechner/pi-ai";
import { Type } from "@mariozechner/pi-ai";
import type { AgentTool } from "@mariozechner/pi-agent-core";
import * as fs from "fs";

const readFileParams = Type.Object({
  path: Type.String({ description: "Path to the file" }),
});

const readFileTool: AgentTool<typeof readFileParams> = {
  name: "read_file",
  label: "Read File",
  description: "Read the contents of a file",
  parameters: readFileParams,
  execute: async (_id, params) => {
    try {
      const content = fs.readFileSync(params.path, "utf-8");
      return {
        content: [{ type: "text", text: content }],
        details: {},
      };
    } catch (err: any) {
      return {
        content: [{ type: "text", text: `Error: ${err.message}` }],
        details: {},
      };
    }
  },
};
// ... (полный пример — см. оригинальную статью)

Управление и продолжение

Если агент работает и вы хотите его перенаправить:

// Interrupt: delivered after the current tool finishes.
// Remaining pending tools are skipped.
agent.steer({
  role: "user",
  content: "Actually, skip that and read tsconfig.json instead.",
  timestamp: Date.now(),
});

// Follow-up: queued for after the agent finishes naturally.
// Doesn't interrupt current work.
agent.followUp({
  role: "user",
  content: "Now summarize what you found.",
  timestamp: Date.now(),
});

steer — прерывает: пропускает оставшиеся инструменты и инжектирует ваше сообщение. followUp — ждёт: ставит сообщение в очередь после естественной остановки. OpenClaw использует steering для сообщений в реальном времени и follow-ups для программной цепочки.

Управление состоянием

Конфигурацию агента можно менять в любое время:

agent.setModel(getModel("openai", "gpt-4o"));  // Switch providers mid-session
agent.setThinkingLevel("high");                // Enable extended thinking
agent.setSystemPrompt("New instructions.");    // Update the system prompt
agent.setTools([...newTools]);                 // Swap the tool set
agent.replaceMessages(trimmedMessages);        // Replace conversation history

Агент подхватывает изменения на следующем обороте.

Слой 3: pi-coding-agent

pi-agent-core даёт вам цикл. pi-coding-agent даёт продакшн-готового агента со встроенными инструментами, персистентностью сессий и расширяемостью. Он построен поверх pi-agent-core.

Большинству пользователей стоит начинать здесь — и опускаться до pi-agent-core только для кастомного агента без встроенных инструментов.

Встроенные инструменты

pi-coding-agent имеет 7 встроенных инструментов. Четыре активны по умолчанию (codingTools), три доступны, но отключены:

Инструменты по умолчанию (активны):

|   Tool   | What it does |
|  `read`  | Read file contents and images (jpg, png, gif, webp). Images are returned as attachments. Text output is truncated to 2000 lines or 50KB. Supports `offset`/`limit` for paginating large files. |
|  `bash`  | Execute a shell command in the working directory. Returns stdout and stderr, truncated to the last 2000 lines or 50KB. Optional `timeout` in seconds. |
|  `edit`  | Replace exact text in a file. `oldText` must match exactly (including whitespace). For precise, surgical edits. |
|  `write` | Write content to a file. Creates it if it doesn't exist, overwrites if it does. Auto-creates parent directories. |

Дополнительные инструменты (opt-in):

|   Tool.  | What it does |
|  `grep`  | Search file contents for a regex or literal pattern. Returns matching lines with file paths and line numbers. Respects `.gitignore`. Uses ripgrep under the hood. |
|  `find`  | Search for files by glob pattern. Returns matching paths relative to the search directory. Respects `.gitignore`. |
|  `ls`    | List directory contents. Entries sorted alphabetically with `/` suffix for directories. Includes dotfiles. |

Они организованы в пресеты:

import { codingTools, readOnlyTools } from "@mariozechner/pi-coding-agent";

codingTools;    // [read, bash, edit, write]  - default
readOnlyTools;  // [read, grep, find, ls]     - exploration without modification

Или выбирайте отдельные инструменты:

import { allBuiltInTools } from "@mariozechner/pi-coding-agent";

// allBuiltInTools.read, allBuiltInTools.bash, allBuiltInTools.edit,
// allBuiltInTools.write, allBuiltInTools.grep, allBuiltInTools.find, allBuiltInTools.ls

const { session } = await createAgentSession({
  model,
  tools: [allBuiltInTools.read, allBuiltInTools.bash, allBuiltInTools.grep],
  sessionManager: SessionManager.inMemory(),
});

createAgentSession

createAgentSession связывает всё воедино — модель, инструменты, персистентность, настройки:

import { createAgentSession, SessionManager } from "@mariozechner/pi-coding-agent";
import { getModel, streamSimple } from "@mariozechner/pi-ai";

async function main() {
  const model = getModel("anthropic", "claude-opus-4-5");

  const { session } = await createAgentSession({
    model,
    thinkingLevel: "off",
    sessionManager: SessionManager.inMemory(),
  });

  session.agent.streamFn = streamSimple;

  session.subscribe((event) => {
    if (event.type === "message_update" && event.assistantMessageEvent.type === "text_delta") {
      process.stdout.write(event.assistantMessageEvent.delta);
    }
    if (event.type === "tool_execution_start") {
      console.log(`\n[${event.toolName}]`);
    }
  });

  await session.prompt("What files are in the current directory? Summarize the package.json.");
  console.log();

  session.dispose();
}

main();

Это рабочий агент кода. Он может читать файлы, выполнять команды, редактировать и писать код. SessionManager.inMemory() означает, что сессия живёт в памяти и исчезает при выходе.

Персистентность сессий

Для долгосрочных сессий направьте SessionManager на файл:

import * as path from "path";

const sessionFile = path.join(process.cwd(), ".sessions", "my-session.jsonl");
const sessionManager = SessionManager.open(sessionFile);

const { session } = await createAgentSession({
  model,
  sessionManager,
});

Сессии хранятся как JSONL-файлы с древовидной структурой — каждая запись имеет id и parentId. Это даёт ветвление: можно перейти в любую точку истории и продолжить оттуда.

SessionManager имеет несколько статических фабричных методов. Выберите нужный и передайте в createAgentSession:

// Option 1: In-memory (ephemeral, nothing written to disk)
const sessionManager = SessionManager.inMemory();

// Option 2: New persistent session in ~/.pi/agent/sessions/
const sessionManager = SessionManager.create(process.cwd());

// Option 3: Open a specific session file
const sessionManager = SessionManager.open("/path/to/session.jsonl");

// Option 4: Continue the most recent session (or create new if none exists)
const sessionManager = SessionManager.continueRecent(process.cwd());

// Then pass whichever one you chose:
const { session } = await createAgentSession({ model, sessionManager });

Также можно получить список существующих сессий для директории:

const sessions = await SessionManager.list(process.cwd());

Как только у вас есть SessionManager, редко нужно вызывать его методы напрямую — createAgentSession обрабатывает большую часть связей. Но если вы строите кастомную логику сессий (как OpenClaw для мульти-канальной маршрутизации), вот ключевые методы:

// Reconstruct the conversation from the JSONL file.
// Use this when you need to inspect or display the current conversation
// outside of the agent session (e.g., showing history in a web UI).
const { messages, thinkingLevel, model } = sessionManager.buildSessionContext();

// Get the last entry in the current branch.
// Useful for checking what the most recent message was,
// or grabbing an entry ID to branch from.
const leaf = sessionManager.getLeafEntry();

// Fork the conversation from a specific point.
// Everything after entryId is abandoned (but still in the file).
// The agent continues from that point on the next prompt.
// OpenClaw uses this for "retry from here" flows.
sessionManager.branch(entryId);

// Manually append a message to the session transcript.
// createAgentSession does this automatically during prompt(),
// but you'd use it to inject messages programmatically -
// e.g., adding a system notification or a cron-triggered prompt.
sessionManager.appendMessage(message);

// Get the full tree structure of the session.
// Each node has children, so you can render a branch selector
// or let users navigate conversation history.
const tree = sessionManager.getTree();

OpenClaw использует один файл сессии на поток канала (~/.openclaw/agents/<agentId>/sessions/<sessionId>.jsonl) — каждый разговор независим и crash-safe (JSONL только дозаписывается; при краше теряется максимум одна строка).

Использование фабрик инструментов

Готовые массивы инструментов codingTools и readOnlyTools — синглтоны. Если нужны инструменты для конкретной директории, используйте фабричные функции:

import {
  createCodingTools,
  createReadOnlyTools,
  createReadTool,
  createBashTool,
  createGrepTool,
} from "@mariozechner/pi-coding-agent";

// Create preset groups scoped to a workspace
const customCodingTools = createCodingTools("/path/to/workspace");       // [read, bash, edit, write]
const customReadOnlyTools = createReadOnlyTools("/path/to/workspace");   // [read, grep, find, ls]

// Or create individual tools - there's a factory for each built-in tool
const customRead = createReadTool("/path/to/workspace");
const customBash = createBashTool("/path/to/workspace");
const customGrep = createGrepTool("/path/to/workspace");

Каждая фабрика принимает опциональный объект operations для переопределения I/O — полезно для запуска внутри Docker, по SSH или против виртуальной файловой системы:

Уплотнение контекста

Длинные разговоры превышают контекстное окно модели. pi-coding-agent решает это через уплотнение контекста:

import { estimateTokens } from "@mariozechner/pi-coding-agent";

// Check how many tokens the conversation uses
const totalTokens = session.messages.reduce(
  (sum, msg) => sum + estimateTokens(msg),
  0
);

// Manually trigger compaction - the optional string guides what the summary should preserve
if (totalTokens > 100_000) {
  await session.compact("Preserve all file paths and code changes.");
}

По умолчанию createAgentSession включает авто-уплотнение — оно срабатывает, когда использование токенов превышает порог. Порог можно настроить.

Расширения (Extensions)

Инструменты позволяют LLM делать вещи. Расширения позволяют вам изменять, как агент использует контекст.

Это место для логики вроде: обрезки старых результатов инструментов, чтобы контекст не переполнялся; инжекции системного состояния перед каждым вызовом LLM; логирования каждого запроса с его полным контекстом.

Расширение — это TypeScript-модуль, экспортирующий функцию, получающую ExtensionAPI:

import type { ExtensionAPI } from "@mariozechner/pi-coding-agent";

export default function myExtension(api: ExtensionAPI): void {
  // Fires before every LLM call. Lets you rewrite the message array.
  api.on("context", (event, ctx) => {
    const pruned = event.messages.filter((msg) => {
      // Drop large tool results older than 10 messages
      if (msg.role === "toolResult" && event.messages.indexOf(msg) < event.messages.length - 10) {
        const text = msg.content.map((c) => (c.type === "text" ? c.text : "")).join("");
        if (text.length > 5000) return false;
      }
      return true;
    });
    return { messages: pruned };
  });

  // Replace the default compaction with your own summarization logic
  api.on("session_before_compact", async (event, ctx) => {
    const summary = await myCustomSummarize(event.messages);
    return { compaction: { summary, firstKeptEntryId: event.firstKeptEntryId, tokensBefore: event.tokensBefore } };
  });

  // Register a user-facing command (not an LLM tool)
  api.registerCommand("stats", {
    description: "Show session statistics",
    handler: async (_args, ctx) => {
      const stats = ctx.session.getSessionStats();
      console.log(`Messages: ${stats.totalMessages}, Cost: $${stats.cost.toFixed(4)}`);
    },
  });
// ... (полный пример — см. оригинальную статью)

Ключевые события расширений: context (перезапись сообщений перед вызовом LLM) и others (перехват результатов инструментов, форматирование вывода).

OpenClaw использует расширения для обрезки контекста, инжекции состояния системы и форматирования вывода инструментов для разных поверхностей (Telegram vs CLI).
